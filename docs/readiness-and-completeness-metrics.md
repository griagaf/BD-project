# Метрики заполненности и готовности

## 1. Общая информация

Метрики используются для оценки состояния военной части, формирования или выбранной области командования. Они отображаются на тактической панели, в паспортах объектов, предупреждениях и сводных отчётах.

Система разделяет два уровня оценки:

- **заполненность** — наличие необходимых данных и ресурсов;
- **готовность** — итоговая оценка состояния с учётом заполненности, предупреждений и инфраструктурных ограничений.

## 2. Метрики заполненности

### Личный состав

**Назначение:** оценить, насколько подразделения укомплектованы военнослужащими.

**Источник данных:** `personnel`, `subdivisions`, `military_units`.

**Формула:**

```text
personnel_completeness = min(100, фактическое_количество / целевой_ориентир * 100)
```

Целевой ориентир определяется уровнем объекта: для части учитывается суммарный состав подчинённых подразделений, для подразделения — фактическое количество военнослужащих в нём.

**Цветовые зоны:**

- зелёная зона: 85–100;
- жёлтая зона: 55–84;
- красная зона: 0–54.

### Техника

**Назначение:** оценить наличие техники в частях текущей области.

**Источник данных:** `equipment_in_units`, `equipment_types`, `equipment_categories`, `military_units`.

**Формула:**

```text
equipment_completeness = части_с_техникой / все_видимые_части * 100
```

Часть без зарегистрированной техники снижает показатель и создаёт предупреждение “В части отсутствует техника”.

### Вооружение

**Назначение:** оценить наличие вооружения в частях.

**Источник данных:** `weapon_in_units`, `weapon_types`, `weapon_categories`, `military_units`.

**Формула:**

```text
weapon_completeness = части_с_вооружением / все_видимые_части * 100
```

Часть без вооружения снижает показатель и создаёт предупреждение “В части отсутствует вооружение”.

### Специалисты

**Назначение:** оценить покрытие специальностей военнослужащими.

**Источник данных:** `specialties`, `personnel_specialties`, `personnel`.

**Формула:**

```text
specialists_completeness = специальности_с_назначенными_специалистами / все_специальности * 100
```

Специальность без военнослужащих отображается в Alert Center.

### Инфраструктура

**Назначение:** оценить пригодность и загрузку сооружений.

**Источник данных:** `buildings`, `subdivision_buildings`, `military_units`.

**Формула:**

```text
infrastructure_completeness = пригодные_сооружения_без_проблем / все_пригодные_сооружения * 100
```

Сооружения с `assignable = false` не считаются пустыми объектами размещения и не снижают показатель из-за отсутствия подразделений.

## 3. Метрики готовности

Итоговая готовность агрегирует направления:

```text
readiness =
  personnel * 0.25 +
  equipment * 0.20 +
  weapons * 0.20 +
  specialists * 0.15 +
  infrastructure * 0.15 -
  alert_penalty
```

Вес предупреждений зависит от severity:

- `CRITICAL`: высокий штраф;
- `HIGH`: значимый штраф;
- `MEDIUM`: умеренный штраф;
- `INFO`: информационное влияние.

**Пороговые зоны:**

- 80–100: высокая готовность;
- 55–79: ограниченная готовность;
- 0–54: критическое состояние.

## 4. Особые случаи

- Non-assignable сооружения не создают предупреждение “сооружение не используется”.
- Отсутствие техники или вооружения в части создаёт actionable alert и снижает readiness.
- Превышение порога по количеству техники или вооружения повышает severity предупреждения.
- Если пользователь видит только часть структуры, расчёт выполняется только в пределах его scope.

## 5. Пример расчёта

Для военной части:

```text
personnel = 88
equipment = 70
weapons = 90
specialists = 75
infrastructure = 82
alert_penalty = 8
```

Промежуточный расчёт:

```text
88 * 0.25 = 22.00
70 * 0.20 = 14.00
90 * 0.20 = 18.00
75 * 0.15 = 11.25
82 * 0.15 = 12.30
subtotal = 77.55
readiness = 77.55 - 8 = 69.55
```

Итог: **70**, зона — ограниченная готовность.

## 6. Техническая реализация

Основные backend-компоненты:

- `DashboardService` — агрегирует показатели панели;
- `AlertService` — формирует предупреждения;
- `SmartMissionReportService` — использует readiness в отчётах;
- inventory services — считают статистику техники и вооружения;
- building services и триггеры — защищают правила размещения подразделений.

Основные endpoints:

- `GET /api/dashboard`;
- `GET /api/dashboard/readiness`;
- `GET /api/alerts`;
- `GET /api/reports/smart-mission`;
- `GET /api/equipment/statistics`;
- `GET /api/weapons/statistics`.

Перерасчёт выполняется при чтении агрегатов и при формировании отчётов. Триггеры БД участвуют в защите целостности данных, а не заменяют сервисные расчёты.
